HOJA RESUMEN · 1/2 · UBUNTU 22.04 · QWEN3-14B Q4_K_M

Preparar A y B → aislar la red

A: coordinador y chat · B: GPU remota. Sigue los pasos de esta hoja en orden; los números de los scripts no indican el orden completo.

Para imprimir: Ctrl+P → A4 → escala 100 %, sin encabezados ni pies del navegador. Dos caras, aptas para imprimir a doble cara.

1. Ambos · preparar los equipos con Internet

Copia la carpeta completa del paquete a ~/prueba_dos_portatiles en ambos. Usa el mismo usuario durante toda la práctica. Conecta los cargadores y desactiva temporalmente la suspensión.

cd "$HOME/prueba_dos_portatiles"
nvidia-smi
nmcli device status

Comprueba la GPU y el nombre de Ethernet. Esta hoja supone eno1. El paquete está preparado para RTX 3060 Laptop de 6 GB. Si el controlador falla o el hardware difiere, consulta la guía antes de continuar.

Usuario normal: no antepongas sudo a los scripts. Introduce la contraseña cuando la pidan.

2. Instalar · pueden hacerlo A y B a la vez

En A
cd "$HOME/prueba_dos_portatiles"
bash ./01_instalar.sh A
En B
cd "$HOME/prueba_dos_portatiles"
bash ./01_instalar.sh B

Espera a que aparezcan CUDA0 e “Instalacion terminada” en ambos. Si falla, conserva el registro y resuelve el error antes de seguir.

3. A · descargar y comprobar el modelo

bash ./02_descargar_modelo_A.sh

Espera a la comprobación correcta de tamaño y SHA-256. Descarga aproximada: 9 GB. B recibe sus pesos desde A durante la carga.

4. B · anotar el usuario y la huella SSH

whoami
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

Usuario de B: __________________   Conserva también la huella mostrada.

5. Ambos · pasar al switch aislado y asignar IP

Solo después de completar las instalaciones y la descarga: conecta un cable de cada portátil al switch encendido, separado de la red del centro. Desactiva Wi-Fi y VPN para aislar completamente los equipos. Ejecuta desde el teclado de cada portátil.

A → 192.168.50.10
bash ./07_configurar_red_aislada.sh A
B → 192.168.50.20
bash ./07_configurar_red_aislada.sh B

Si Ethernet tiene otro nombre, añádelo al comando, por ejemplo: bash ./07_configurar_red_aislada.sh B enp3s0.

6. A · comprobar comunicación con B

ping -c 3 192.168.50.20

Si no responde, revisa IP, cables y cortafuegos. El filtrado de ping puede impedir la respuesta aunque SSH funcione.

Los perfiles anteriores se conservan. Mantén ~/cluster_llm/red en cada equipo para restaurar DHCP. Continúa por el paso 7 de la siguiente cara.
HOJA RESUMEN · 2/2 · EJECUCIÓN SIN INTERNET Y FINALIZACIÓN

Arrancar B → conectar A → probar → restaurar

7. B · terminal B1: arrancar la GPU remota

cd "$HOME/prueba_dos_portatiles"
sudo systemctl start ssh
bash ./03_iniciar_rpc_B.sh

Espera a que aparezcan CUDA0 y 127.0.0.1:50052. Deja B1 abierta.

8. A · terminal A1: abrir el túnel SSH

Sustituye USUARIO_B por el resultado de whoami del paso 4.

cd "$HOME/prueba_dos_portatiles"
bash ./04_abrir_tunel_A.sh USUARIO_B@192.168.50.20

Compara la huella con la anotada en B y acepta si coincide. Introduce la contraseña de B; puede pedirla dos veces. Deja A1 abierta, aunque no muestre más texto.

9. A · nueva terminal A2: cargar el modelo

cd "$HOME/prueba_dos_portatiles"
bash ./05_iniciar_modelo_A.sh

Espera a que el servidor esté listo; la primera carga puede tardar varios minutos. Deja A2 abierta. Abre en el navegador de A: http://127.0.0.1:8080.

10. Probar y observar las GPU

A · nueva terminal A3
cd "$HOME/prueba_dos_portatiles"
bash ./06_probar_A.sh

Guarda resultados en ~/cluster_llm/resultados. No uses el chat mientras se mide.

Ambos · terminal adicional
watch -n 1 nvidia-smi

Comprueba VRAM ocupada en ambas GPU. Ctrl+C cierra esta observación.

11. Parar · orden obligatorio antes de cambiar la red

Ctrl+C en A2 (modelo) → Ctrl+C en A1 (túnel) → Ctrl+C en B1 (RPC). Conserva los registros de ~/cluster_llm/logs y los resultados.

12. Ambos · volver a la red habitual y a DHCP

Conecta cada cable a una red con servidor DHCP. En una terminal local de cada portátil:

cd "$HOME/prueba_dos_portatiles"
bash ./08_restaurar_dhcp.sh

Si utilizaste otra interfaz: bash ./08_restaurar_dhcp.sh enp3s0. Espera “Conexion DHCP activa”. En el switch aislado puede quedar pendiente: conecta a la red habitual y repite 08. Restaura Wi-Fi, VPN y suspensión si las cambiaste.

Solo si hay un problema: si UFW bloquea SSH, en otra terminal de B consulta sudo ufw status; si procede, permite A con sudo ufw allow from 192.168.50.10 to any port 22 proto tcp. Si añadiste esa regla solo para la prueba, al acabar retírala con sudo ufw delete allow from 192.168.50.10 to any port 22 proto tcp. No abras RPC al exterior. Para otros errores, consulta la guía completa.
Otra sesión: con instalación y modelo conservados, empieza por el paso 5 de esta hoja. Prueba real en los portátiles pendiente; consulta GUIA_PASO_A_PASO.html y COMPROBACIONES.txt para detalles.
